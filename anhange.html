    13. Anhänge

    13.1. PHP installieren

    Die Beispiele und die Fallstudie erfordern [PHP] 8.4 oder höher ([Symfony] 8 setzt dies voraus) mit den Erweiterungen [intl] (Formatierung von Zahlen und Datumsangaben, Beispiel 16, und ICU-Nachrichten, Beispiel 22), [pdo_mysql] (Zugriff auf [MySQL], Beispiel 28 und Fallstudie), [mbstring], und [openssl]. Sie wurden mit der Version 8.4 getestet.

    Unter [Windows] ist [Laragon] (laragon.org) am einfachsten; es installiert [PHP], [Composer], einen [MySQL]-Server und das Administrationswerkzeug [HeidiSQL]. Ist die mitgelieferte Version von [PHP] älter als 8.4, laden Sie eine neuere Version von windows.php.net/download herunter (Thread-Safe-Version, Archiv [.zip]) und entpacken Sie sie in den Ordner [bin\php] von [Laragon]; über das Menü PHP / Version in [Laragon] können Sie sie anschließend auswählen. Das Menü PHP / Extensions aktiviert eine Erweiterung mit einem einzigen Klick ([intl], [pdo_mysql]). Das Terminal von [Laragon] (Schaltfläche Terminal) unterstützt die Befehle [php], [composer], und [mysql].

    Ohne [Laragon] entpacken Sie das Archiv von [PHP] in einen Ordner ([C:\php]), fügen diesen Ordner zur Umgebungsvariablen [Path] hinzu, erstellen dann die Konfigurationsdatei [php.ini] durch Kopieren von [php.ini-development] und entfernen das Semikolon, das die Zeilen der benötigten Erweiterungen auskommentiert:

    1
2
3
4
    extension=intl
extension=mbstring
extension=openssl
extension=pdo_mysql

    Unter [macOS] erledigt der Paketmanager [Homebrew] die Installation von [PHP] samt seinen Standarderweiterungen: [brew install php]. Unter [Linux] ([Ubuntu]) ist die von der Distribution bereitgestellte Version oft älter; das Repository [ppa:ondrej/php] liefert die neuesten Versionen:

    1
2
    sudo add-apt-repository ppa:ondrej/php
sudo apt install php8.4-cli php8.4-intl php8.4-mbstring php8.4-mysql php8.4-xml php8.4-curl php8.4-zip

    Überprüfen Sie die Installation in einer neuen Konsole:

    1
2
    php -v
php -m

    Der erste Befehl sollte eine Versionsnummer größer oder gleich 8.4 anzeigen (zum Beispiel [PHP 8.4.12]); der zweite listet die geladenen Erweiterungen auf, darunter [intl] und [pdo_mysql]. Der Befehl [php --ini] zeigt an, welche Datei, [php.ini], verwendet wird.

    13.2. Composer

    [Composer] ist der Bibliotheksmanager für [PHP] (getcomposer.org). Er wird von [Laragon] mitgeliefert; unter [Windows] verwendet man ohne [Laragon] dessen Installationsprogramm ([Composer-Setup.exe]); unter [macOS] verwenden Sie [brew install composer]; unter [Linux] folgen Sie den Anweisungen auf der Seite getcomposer.org/download. Überprüfen Sie die Installation:

    1
    composer -V

    Nützliche Befehle in einem Projektordner (dem Ordner, der [composer.json] enthält):

    1
2
3
4
5
    composer install              # die Bibliotheken des Projekts installieren (Ordner vendor)
composer show                 # die installierten Bibliotheken
composer update               # auf die neuesten von composer.json erlaubten Versionen aktualisieren
composer require name/package # dem Projekt eine Bibliothek hinzufügen
composer dump-autoload        # den Class Loader neu erstellen (nach dem Hinzufügen eines Klassenordners)

    [Composer] lädt die Bibliotheken aus dem Repository [Packagist] (packagist.org) herunter: Während der Installation ist eine Internetverbindung erforderlich. Befinden Sie sich hinter einem Firmen-Proxy, geben Sie den Proxy über die Umgebungsvariablen [HTTP_PROXY] und [HTTPS_PROXY] an. Der Ordner [vendor] wird nicht von einem Rechner auf einen anderen kopiert (er kann absolute Pfade enthalten und ist umfangreich); er wird mit [composer install] neu erstellt. Deshalb ist er nicht in den Kursmaterialien enthalten. Der Ordner [examples] hat einen eigenen Ordner [vendor], der von allen 28 Beispielen gemeinsam genutzt wird; die Fallstudie hat ihren eigenen.

    Die Fallstudie verwendet die Komponente [Runtime] von [Symfony], die zugleich ein Plugin für [Composer] ist: Diese Komponente erzeugt die Datei [vendor/autoload_runtime.php], die von [public/index.php] gelesen wird. [Composer] fordert die Erlaubnis an, ein Plugin auszuführen; die Datei [composer.json] der Anwendung erteilt sie (Abschnitt [allow-plugins]). Unter [Linux] weigert sich [Composer] , Plugins auszuführen, wenn es vom Konto [root] aus gestartet wird, es sei denn, die Umgebungsvariable [COMPOSER_ALLOW_SUPERUSER] ist auf [1] gesetzt: Ohne sie würde die Datei [autoload_runtime.php] fehlen (siehe „Häufige Probleme“ in der Fallstudie). Am besten arbeitet man nicht unter dem Konto [root].

    13.3. Visual Studio Code installieren

    [Visual Studio Code] wird von code.visualstudio.com heruntergeladen. Fügen Sie drei Erweiterungen hinzu (Menü View / Extensions):

    • PHP Intelephense: Code-Vervollständigung, Code-Navigation (einschließlich des Codes von [Symfony] im Ordner [vendor]) und Fehlermeldungen;
    • Twig Language 2: Syntaxhervorhebung und Vervollständigung für [Twig]-Views ([.html.twig]-Dateien);
    • YAML (von [Red Hat]): Syntaxhervorhebung und Validierung von Konfigurationsdateien ([config/packages/*.yaml]) und Wörterbüchern ([translations/*.yaml]).

    Mit der Erweiterung PHP Debug können Sie den Code mit dem Debugger [Xdebug] Schritt für Schritt ausführen (eine Erweiterung von [PHP], die separat zu installieren ist: xdebug.org).

    Öffnen Sie den Ordner [examples] oder den Ordner der Fallstudie (Menü File / Open Folder). Das integrierte Terminal (Menü Terminal / New Terminal) ermöglicht es Ihnen, Anwendungen zu starten und [php bin/console ...]-Befehle auszuführen, ohne den Editor zu verlassen.

    13.4. MySQL mit Laragon installieren

    [Laragon] installiert einen sofort einsatzbereiten [MySQL]-Server unter [Windows] sowie das Administrationswerkzeug [HeidiSQL]. Nach der Installation:

    • die Schaltfläche „Start All“ startet den [MySQL]-Server auf Port 3306;
    • der Benutzer [root] hat kein Passwort: Dies sind die Werte der Variablen [DATABASE_URL] aus den [.env]-Dateien in Beispiel 28 und der Fallstudie ([mysql://root:@127.0.0.1:3306/...]);
    • die Schaltfläche Database öffnet [HeidiSQL], wo das Menü File / Run File SQL die Skripte [dbpersons.sql] (Beispiel 28) und [dbrdvmedecins2.sql] (Fallstudie) ausführt.

    Unter [Linux] oder [macOS] installieren Sie [MySQL] oder [MariaDB] mit dem Paketmanager des Systems und führen die Skripte mit dem Kommandozeilenclient [mysql] aus. Der Treiber [pdo_mysql] funktioniert mit beiden ohne jede Konfiguration. Unter [Linux] ist das Konto [root] von [MariaDB] oft so konfiguriert, dass die Anmeldung nur über das Systemkonto [root] erfolgt ([sudo mysql]): Dann wird ein Benutzer für die Anwendungen angelegt und in der Variablen [DATABASE_URL] in deren Datei [.env] ([mysql://course:course@127.0.0.1:3306/...]) angegeben:

    1
    sudo mysql -e "CREATE USER 'course'@'localhost' IDENTIFIED BY 'course'; GRANT ALL ON *.* TO 'course'@'localhost';"

    Bei [MariaDB] geben Sie in der Variablen [DATABASE_URL] außerdem deren Version an ([serverVersion=10.11.2-MariaDB] statt [serverVersion=8.0.32], zum Beispiel): [Doctrine] passt das von ihm erzeugte SQL an die verwendete Datenbank an.

    13.5. curl installieren

    [curl] ist in [Windows] 10 und 11, [macOS] und den meisten [Linux]-Distributionen enthalten. In [PowerShell] müssen Sie [curl.exe] eingeben, nicht [curl]: In älteren Versionen von [PowerShell] ist [curl] ein Alias für einen anderen Befehl ([Invoke-WebRequest]), der andere Optionen hat. In der Eingabeaufforderung von [Windows] ([cmd]) werden die Anführungszeichen einer JSON-Zeichenkette als [\"] geschrieben (Beispiel 11), und eine URL, die [&] enthält, muss in doppelte Anführungszeichen gesetzt werden.

    13.6. Das Tool symfony

    [Symfony] stellt ein Kommandozeilenwerkzeug bereit, das Programm [symfony] (Symfony CLI), das zum Nachvollziehen dieses Dokuments nicht erforderlich ist, in der gesamten Dokumentation aber referenziert wird. Es wird gemäß den Anweisungen auf der Seite symfony.com/download installiert: unter [Windows] mit dem Paketmanager [Scoop] ([scoop install symfony-cli]); unter [macOS] mit [Homebrew] ([brew install symfony-cli/tap/symfony-cli]); unter [Linux] mit dem Paketmanager des Systems. Die nützlichsten Befehle:

    1
2
3
4
    symfony check:requirements      # ist die PHP-Konfiguration für Symfony geeignet?
symfony new my-project --webapp # ein neues vollständiges Projekt (siehe Einleitung)
symfony server:start            # ein Entwicklungsserver (http://127.0.0.1:8000)
symfony console debug:router    # entspricht php bin/console debug:router

    Sein Entwicklungsserver leistet dasselbe wie [php -S localhost:8000 -t public], mit einigen Vorteilen: Er findet den Ordner [public] selbstständig, er kann die Site über HTTPS ausliefern (nach [symfony server:ca:install]), er kann im Hintergrund laufen ([symfony server:start -d], dann [symfony server:stop]), und er wählt die [PHP]-Version des Projekts aus, wenn mehrere Versionen installiert sind. Der in [PHP] integrierte Server, der in diesem Dokument verwendet wird, hat den Vorteil, dass er keine Installation erfordert.
