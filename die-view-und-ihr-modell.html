    4. Die View und ihr Modell

    Bisher haben die Actions ihre Antworten selbst erzeugt: Text, JSON und einige HTML-Tags, als Zeichenkette geschrieben. In einer MVC-Anwendung ist dies die Aufgabe einer View: einer Datei, die das HTML der Seite beschreibt, mit Platzhaltern für die Daten, die ihr die Action übergibt – das Modell der View.

    [Symfony] verwendet die View-Engine [Twig], die vom selben Team entwickelt wurde. Eine [Twig]-View ist eine Datei, deren Name auf [.html.twig] endet (das Ausgabeformat, gefolgt von der Engine) und die im Ordner [templates] der Anwendung gespeichert ist. Es ist eine Textdatei – in diesem Fall HTML –, in der drei Arten von Tags auf dem Server interpretiert werden:

    • [{{ expression }}]: der Wert eines Ausdrucks, der in die Seite eingefügt wird;
    • [{% instruction %}]: eine Anweisung (Tag); eine Bedingung ([{% if %}]); eine Schleife ([{% for %}]), Template-Vererbung ([{% extends %}], [{% block %}]), Einbindung ([{% include %}]) ...;
    • [{# comment #}]: ein Kommentar, der auf der erzeugten Seite nicht erscheint.

    Alles andere wird unverändert übernommen. Die Ausdrücke sind nicht in [PHP] geschrieben, sondern in der Sprache von [Twig], die einfacher und sicherer ist: [model.title] bezeichnet die Eigenschaft [title] des Objekts [model] (oder seine Methode [getTitle()] oder den Schlüssel [title] eines Arrays: [Twig] sucht es selbst heraus); Filter transformieren einen Wert ([name|upper] wandelt einen Namen in Großbuchstaben um); Funktionen führen Berechnungen durch ([path('home')] erzeugt eine URL). [Twig] ähnelt damit [Jinja2] ([Flask]), von dem es sich inspirieren ließ, oder der Engine von [Django]; es unterscheidet sich von [Blade] ([Laravel]) und [Razor] ([ASP.NET Core]), die HTML mit Code der Host-Sprache mischen. Eine [Twig]-View kann nicht beliebigen [PHP]-Code ausführen: Sie kann nur die ihr übergebenen Daten anzeigen. Das ist beabsichtigt: Die Anwendungslogik bleibt in den Klassen. Eine View wird nicht bei jeder Anfrage interpretiert: Bei der ersten Verwendung kompiliert [Twig] sie in eine [PHP]-Klasse, die im Ordner [var/cache/dev/twig] abgelegt wird und die es wiederverwendet, solange die View unverändert bleibt. Wir werden sehen, wie diese Datei aussieht.

// src/Controller/ViewsController.php: Actions, die eine VIEW zurückgeben

namespace App\Controller;

use App\Model\PageModel;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

#[Route(methods: ['GET'])]
class ViewsController extends AbstractController
{
    // render: Die Twig-Engine baut die Seite aus dem View-Template
    // templates/views/index.html.twig und aus den im Array übergebenen Variablen (hier
    // nur eine, [model]); die erzeugte Seite ist der Body der Antwort
    #[Route('/', name: 'index')]
    public function index(): Response
    {
        $model = new PageModel(
            'My first view',
            'This page was built by Twig, on the server.',
            date('H:i:s'));
        return $this->render('views/index.html.twig', ['model' => $model]);
    }

    // dieselbe View mit einem anderen Modell; oder eine andere View, mit dem Code 404
    #[Route('/hello/{name}', name: 'hello')]
    public function hello(string $name): Response
    {
        if ($name === 'unknown') {
            // der dritte Parameter von render: die zu vervollständigende Antwort, hier mit dem Code 404
            return $this->render('views/unknown.html.twig', ['name' => $name],
                new Response(status: Response::HTTP_NOT_FOUND));
        }
        $model = new PageModel(
            "Hello $name",
            'This time, the title of the page comes from the URL.',
            date('H:i:s'));
        return $this->render('views/index.html.twig', ['model' => $model]);
    }
}
    • Zeilen 20–23: Die Action erstellt das Modell der View. Die Funktion [date], aus [PHP] übernommen, formatiert die aktuelle Uhrzeit: [H] formatiert die Stunden, [i] formatiert die Minuten und [s] formatiert die Sekunden;
    • Zeile 24: Die Methode [render] von [AbstractController] weist [Twig] an, die Seite zu erzeugen. Der erste Parameter ist der Name der View: der Dateipfad, relativ zum Ordner [templates]. Der zweite Parameter ist ein assoziatives Array, dessen Schlüssel jeweils zu einer Variablen in der View wird – hier nur eine: [model]. [render] liefert ein Objekt [Response] zurück, dessen Body die erzeugte Seite ist (vom Typ [text/html]);
    • Zeilen 31–35: eine weitere View mit einer weiteren Variablen ([name]). Der dritte Parameter von [render] ist eine zu befüllende Antwort: hier eine 404-Antwort für eine benutzerdefinierte Fehlerseite. [new Response(status: ...)] übergibt den Code über einen benannten Parameter, während die übrigen Parameter ihre Standardwerte behalten;
    • Zeilen 36–40: dieselbe View wie bei der Action [index], aber mit einem anderen Modell. Das ist der Vorteil der Trennung von Actions und Views: Eine einzige View kann von mehreren Actions verwendet werden.

    • Zeile 15: Ein Wert [null] wird als leere Zeichenkette angezeigt. Der Filter [default] ersetzt einen leeren (oder fehlenden) Wert durch einen Standardwert;
    • Zeilen 17–18: [{{ }}] maskiert HTML (2a); der Filter [raw], fügt den Wert dagegen unverändert ein, ohne ihn zu maskieren (2b). [raw] ist dem von der Anwendung selbst erzeugten HTML vorbehalten, niemals für Benutzereingaben;
    • Zeilen 20–24: eine Bedingung: [{% if %}], [{% elseif %}], [{% else %}], [{% endif %}]. Jeder Block wird durch eine Anweisung [{% end... %}] geschlossen;
    • Zeilen 28–34: eine Schleife [{% for ... in ... %}] ... [{% endfor %}]. Innerhalb der Schleife beschreibt die spezielle Variable [loop] den Zustand der Schleife: [loop.index0] (die Nummer des Durchlaufs, bei 0 beginnend), [loop.index] (bei 1 beginnend), [loop.first], [loop.last] (true beim ersten bzw. letzten Durchlauf), [loop.length] (die Anzahl der Elemente). Variablen außerhalb der Schleife ([model.name]) bleiben zugänglich;
    • Zeile 30: der ternäre Operator [condition ? a : b] ([Twig] akzeptiert auch [condition ? a], was eine leere Zeichenkette liefert, wenn die Bedingung falsch ist);
    • Zeile 38: Eine Schleife [for] kann einen Block [{% else %}]haben, der ausgeführt wird, wenn die Liste leer ist. Das ist einfacher als ein [{% if %}] , das die Länge der Liste prüfen würde;
    • Zeilen 41–42: berechnete Ausdrücke ([total / count]) und die Variablen aus [set]. Der Filter [number_format] formatiert eine Zahl: zwei Nachkommastellen, einen Punkt als Dezimaltrennzeichen und ein Komma als Tausendertrennzeichen. In Beispiel 16 werden wir eine viel bessere Möglichkeit sehen, Zahlen und Beträge zu formatieren;
    • Zeile 44: Der Punkt durchläuft Objekte ([model.address.city]), und der Filter [upper] wandelt eine Zeichenkette in Großbuchstaben um (wobei Zeichen mit Akzenten korrekt behandelt werden);
    • Zeile 46: Die Anweisung [{% verbatim %}] kopiert ihren Inhalt, ohne ihn zu interpretieren: Das ist nützlich, wenn eine Seite geschweifte Klammern enthält, die für ein [JavaScript]-Framework bestimmt sind.

    [Twig] hat etwa fünfzig Filter ([lower], [capitalize], [trim], [join], [split], [slice], [sort], [date], [json_encode], [escape]...), etwa fünfzehn Funktionen ([range], [min], [max], [random]...) und Tests ([is defined], [is empty], [is null], [is iterable], [is even]...); die Bundles von [Symfony] ergänzen einige ([path], [asset], [form_row], [is_granted]...), und die Anwendung kann eigene schreiben (Beispiel 16).

    #[Route('/bootstrap/{file}', name: 'bootstrap', requirements: ['file' => Requirement::CATCH_ALL],
        methods: ['GET'])]
    public function serve(string $file): BinaryFileResponse
    {
        $folder = realpath(__DIR__.'/bootstrap');
        // realpath: der absolute Pfad der angeforderten Datei, ohne . und ..;
        // false, wenn die Datei nicht existiert
        $path = realpath($folder.'/'.$file);
        // eine Datei, die existiert und tatsächlich IM Ordner liegt (kein ../, um aus ihm auszubrechen)
        if ($path === false || ! str_starts_with($path, $folder.DIRECTORY_SEPARATOR) || ! is_file($path)) {
            throw new NotFoundHttpException("unknown file: $file");
        }
        // eine Antwort, die den Inhalt einer Datei sendet; ihr Typ richtet sich nach der Dateiendung
        $response = new BinaryFileResponse($path);
        $types = ['css' => 'text/css', 'js' => 'text/javascript', 'map' => 'application/json'];
        $response->headers->set('Content-Type', $types[pathinfo($path, PATHINFO_EXTENSION)] ?? 'application/octet-stream');
        return $response;
    }
}

// zwei Filter hinzufügt: money und long_date

namespace App\Twig;

use DateTimeInterface;
use IntlDateFormatter;
use NumberFormatter;
use Symfony\Component\HttpFoundation\RequestStack;
use Twig\Extension\AbstractExtension;
use Twig\TwigFilter;

class FormatsExtension extends AbstractExtension
{
    // der Request-Stack, um die Sprache der aktuellen Anfrage zu kennen
    public function __construct(private RequestStack $requests)
    {
    }

    // die Filter der Extension: ihr Name in den Views und die Methode, die sie implementiert
    public function getFilters(): array
    {
        return [
            new TwigFilter('money', $this->money(...)),
            new TwigFilter('long_date', $this->longDate(...)),
        ];
    }

    // ein Betrag in Cent in einer Währung, im Format der Sprache der
    // Anfrage: 114990 -> "€1,149.90" auf Englisch, "1 149,90 €" auf Französisch.
    // Die PHP-Erweiterung intl kennt die Konventionen jedes Landes
    public function money(int $cents, string $currency = 'EUR'): string
    {
        $formatter = new NumberFormatter($this->language(), NumberFormatter::CURRENCY);
        return $formatter->formatCurrency($cents / 100, $currency);
    }

    // ein Datum in ausgeschriebenen Wörtern, in der Sprache der Anfrage: "Sunday, September 27, 2026"
    public function longDate(DateTimeInterface $day): string
    {
        $formatter = new IntlDateFormatter($this->language(), IntlDateFormatter::FULL, IntlDateFormatter::NONE);
        return $formatter->format($day);
    }

    private function language(): string
    {
        return $this->requests->getCurrentRequest()?->getLocale() ?? 'en';
    }
}

    // der URL-Parameter ?lang=fr, sonst Englisch

            && ($genre === '' || $book->genre === $genre)));
        return $this->render('books/search.html.twig', [
            'model' => new SearchModel($keyword, $genre, self::GENRES, $results),
        ]);
    }
}

namespace App\Form;

use App\Service\ListsService;
use Symfony\Component\Form\AbstractType;
use Symfony\Component\Form\Extension\Core\Type\ChoiceType;

    public function buildForm(FormBuilderInterface $builder, array $options): void

            // ein Passwort: wird in der Seite nie wieder angezeigt
            ->add('password', PasswordType::class, ['label' => 'Password', 'required' => false])
            // ein Datum: ein Feld <input type="date">; der Wert ist ein String im Format yyyy-mm-dd
            ->add('birth_date', DateType::class, [
                'label' => 'Date of birth',

                'input' => 'string',

            ])
            // Checkboxen: eine expandierte Liste von Auswahlmöglichkeiten mit MEHRFACHAUSWAHL
            ->add('hobbies', ChoiceType::class, [
                'choices' => $this->lists->hobbies(),
                'expanded' => true,
                'multiple' => true,
                'label_attr' => ['class' => 'checkbox-inline'],
                'required' => false,
            ])
            // Dropdown-Liste: eine Liste von Auswahlmöglichkeiten, die nicht expandiert ist
            ->add('country', ChoiceType::class, ['choices' => $this->lists->countries()])
            // Mehrfachauswahlliste, auf vier Zeilen angezeigt
            ->add('languages', ChoiceType::class, [
                'label' => 'Spoken languages',
                'choices' => $this->lists->languages(),
                'multiple' => true,
                'attr' => ['size' => 4],
                'required' => false,
            ])
            ->add('comment', TextareaType::class, ['required' => false, 'attr' => ['rows' => 2]])
            // ein verstecktes Feld
            ->add('token', HiddenType::class);

// src/Controller/FormController.php: ein Formular, das alle Feldtypen verwendet

namespace App\Controller;

use App\Form\FieldsType;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

class FormController extends AbstractController
{
    // GET: das Formular mit Anfangswerten; POST: Die gesendeten Felder
    // werden gelesen, validiert und dann vom selben Formular erneut angezeigt
    #[Route('/form', name: 'form', methods: ['GET', 'POST'])]
    public function form(Request $request): Response
    {
        // die Anfangswerte (einer pro Feld, ein Array für ein Mehrfachfeld)
        $initial = ['title' => 'Mme', 'country' => 'fr', 'languages' => ['French'], 'token' => 'A7X2'];
        // createForm: das Formular, aus seiner Beschreibung gebaut
        $form = $this->createForm(FieldsType::class, $initial);
        // handleRequest: Ist die Anfrage ein POST, werden die empfangenen Felder
        // in das Formular kopiert und dann validiert
        $form->handleRequest($request);
        $model = ['form' => $form];
        if ($form->isSubmitted()) {
            // was der Browser tatsächlich gesendet hat, Feld für Feld
            $received = [];
            foreach ($request->request->all() as $name => $value) {
                foreach ((array) $value as $key => $v) {
                    $received[] = "{$name}[$key] = [".implode(', ', (array) $v).']';
                }
            }
            $model += [
                'received' => implode("\n", $received),
                'valid' => $form->isValid(),
                // getErrors(true): die Fehler aller Felder
                'errors' => $form->getErrors(true),
                // getData(): die Werte des Formulars, von jedem Feld umgewandelt
                'data' => $form->getData(),
            ];
        }
        return $this->render('form/form.html.twig', $model);
    }
}

    • Zeile 22: [createForm] erzeugt das Formular – ein Objekt [Form] – anhand seines Typs und der Anfangsdaten;
    • Zeile 25: [handleRequest] untersucht die Anfrage. Bei einem GET tut es nichts. Bei einem POST, der die Formularfelder enthält, kopiert es sie in das Formular: Jedes Feld konvertiert seinen Wert (das Datum, die Listen usw.) und prüft, ob eine Auswahl zu den angebotenen gehört; danach validiert das Formular die Constraints und das Anti-CSRF-Token;
    • Zeile 27: [isSubmitted]: Wurde das Formular gesendet?;
    • Zeilen 29–34: für dieses Beispiel die Liste dessen, was der Browser tatsächlich gesendet hat. Die Felder eines [Symfony]-Formulars sind nach dem Formular benannt: [fields[name]], [fields[hobbies][]]. [PHP] organisiert sie daher in einem Array namens [fields] (Beispiel 10), das anschließend durchlaufen wird.     4.8. Beispiel 20: Das Post/Redirect/Get-Muster

    Wenn eine POST-Aktion mit einer Seite antwortet, ist diese Seite das Ergebnis eines POST. Lädt der Benutzer die Seite neu (drückt [F5]), sendet der Browser die POST-Anfrage erneut, nachdem er eine Warnung angezeigt hat, die kaum jemand liest: Der Befehl wird zweimal gesendet, und die Nachricht wird zweimal veröffentlicht. Das Post/Redirect/Get-Muster (PRG) vermeidet dieses Problem: Eine erfolgreiche POST-Aktion liefert keine Seite zurück, sondern antwortet mit einer Weiterleitung (Beispiel 04) auf eine GET-Seite, die der Browser sofort abruft. Das Neuladen dieser Seite führt lediglich die GET-Aktion erneut aus.

    Ein Problem bleibt: Die GET-Seite möchte eine Nachricht anzeigen („Die Aufgabe wurde hinzugefügt“), aber diese Nachricht kennt die POST-Aktion, und sie kann keine Variable an eine Anfrage übergeben, die noch nicht stattgefunden hat. Die Lösung: Die Flash-Nachricht, die von der POST-Aktion in der Session abgelegt wird, bleibt erhalten, bis sie gelesen und angezeigt wurde, und wird dann verworfen.

// Benutzern gemeinsam genutzt wird. In PHP überleben Objekte die Anfrage nicht: Die Liste wird
// im CACHE der Anwendung gespeichert (hier eine Datei im Ordner var/cache/dev/pools)

namespace App\Service;

use Psr\Cache\CacheItemPoolInterface;
use Symfony\Component\Lock\LockFactory;

class TasksService
{
    private const KEY = 'tasks';

    // der Cache der Anwendung (der Service cache.app) und die Lock-Factory
    public function __construct(
        private CacheItemPoolInterface $cache,
        private LockFactory $locks,
    ) {
    }

    /** @return list<string> */
    public function list(): array
    {
        // das unter dem Schlüssel [tasks] gespeicherte Cache-Element; isHit: Es existiert
        $item = $this->cache->getItem(self::KEY);
        return $item->isHit() ? $item->get() : ['Read chapter 3'];
    }

    public function add(string $label): void
    {
        // Mehrere Anfragen können GLEICHZEITIG laufen (der Server verarbeitet
        // sie in mehreren Prozessen): Ein Lock garantiert, dass immer nur eine
        // die Liste liest, ändert und zurückschreibt
        $lock = $this->locks->createLock('tasks');
        // acquire(true): warten, bis der Lock frei ist, und ihn dann nehmen
        $lock->acquire(true);
        try {
            $tasks = $this->list();
            $tasks[] = $label;
            // das Cache-Element erhält seinen neuen Wert, ohne Zeitbegrenzung
            $item = $this->cache->getItem(self::KEY);
            $this->cache->save($item->set($tasks));
        } finally {
            // finally: Der Lock wird in jedem Fall freigegeben, auch nach einer Exception
            $lock->release();
        }
    }
}

Standardmäßig speichert er seine Werte in Dateien im Ordner [var/cache/dev/pools]; in der Produktion wird ein dedizierter Server bevorzugt, etwa [Redis] (eine Konfigurationszeile). Der zweite ist die Lock-Factory der Lock-Komponente;
    • Zeilen 23–28: [getItem] ruft das Cache-Element ab, das unter einem Schlüssel gespeichert ist; [isHit] prüft, ob es existiert, und [get] liefert seinen Wert. Es kann jeder beliebige Wert gespeichert werden (hier ein Array von Zeichenketten): [Symfony] serialisiert ihn – das heißt, es wandelt ihn in Text um – mit der Funktion [serialize] von [PHP];

use App\Model\Contact;
use Psr\Cache\CacheItemPoolInterface;
use Symfony\Component\Lock\LockFactory;

class ContactsService
{
    private const KEY = 'contacts';

    public function __construct(
        private CacheItemPoolInterface $cache,
        private LockFactory $locks,
    ) {
    }

    /** @return array{contacts: list<Contact>, lastId: int} */
    private function data(): array
    {
        $item = $this->cache->getItem(self::KEY);
        return $item->isHit() ? $item->get() : [
            'contacts' => [
                new Contact(1, 'Marie Durand', '01 23 45 67 89'),
                new Contact(2, 'Paul Martin', '06 12 34 56 78'),
                new Contact(3, 'Philippe Jandot', '02 98 76 54 32'),
            ],
            'lastId' => 3,
        ];
    }

    // eine Änderung der Daten unter Lock: Die Funktion erhält die Daten,
    // ändert sie (&) und gibt das Ergebnis der Operation zurück
    private function editData(callable $operation): mixed
    {
        $lock = $this->locks->createLock('contacts');
        $lock->acquire(true);
        try {
            $data = $this->data();
            $result = $operation($data);
            $this->cache->save($this->cache->getItem(self::KEY)->set($data));
            return $result;
        } finally {
            $lock->release();
        }
    }

    /** @return list<Contact> */
    public function list(): array
    {
        return $this->data()['contacts'];
    }

    // der Kontakt oder null, wenn er nicht existiert
    public function read(int $id): ?Contact
    {
        return array_find($this->list(), fn (Contact $c) => $c->id === $id);
    }

    public function edit(int $id, string $name, string $phone): ?Contact
    {
        return $this->editData(function (array &$data) use ($id, $name, $phone) {
            foreach ($data['contacts'] as $i => $contact) {
                if ($contact->id === $id) {
                    // Ein Kontakt ist unveränderlich (readonly): Wir bauen einen neuen,
                    // der den alten im Array ersetzt
                    return $data['contacts'][$i] = new Contact($id, $name, $phone);
                }
            }
            return null;
        });
    }

    public function add(string $name, string $phone): Contact
    {
        return $this->editData(function (array &$data) use ($name, $phone) {
            $contact = new Contact(++$data['lastId'], $name, $phone);
            $data['contacts'][] = $contact;
            return $contact;
        });
    }

    public function delete(int $id): ?Contact
    {
        return $this->editData(function (array &$data) use ($id) {
            foreach ($data['contacts'] as $i => $contact) {
                if ($contact->id === $id) {
                    // array_splice entfernt das Element i aus dem Array und nummeriert die folgenden neu
                    array_splice($data['contacts'], $i, 1);
                    return $contact;
                }
            }
            return null;
        });
    }
}

    Die Kontakte werden im Cache gespeichert, genau wie die Aufgaben in Beispiel 20. Jeder Kontakt ist ein unveränderliches Objekt [Contact] (eine ID, ein Name, eine Telefonnummer), gespeichert in einem Array zusammen mit der zuletzt vergebenen ID. Einige Anmerkungen zu [PHP]:

    • Zeilen 37–49: Alle Änderungen folgen demselben Muster: Sperre erwerben, Daten lesen, ändern, zurückschreiben und die Sperre freigeben. Diese Methode schreibt einmal in das Array; jeder Änderung wird eine Funktion übergeben (vom Typ [callable], „aufrufbar“), die die Daten erhält und ändert. Die Funktion muss das Array selbst ändern, nicht eine Kopie: Ihr Parameter ist als [array &$data] deklariert, wobei [&] eine Übergabe per Referenz angibt (ohne [&] wird ein Array kopiert; siehe Beispiel 06). Das Schlüsselwort [use] in einer anonymen Funktion gibt ihr Zugriff auf Variablen der umgebenden Funktion (Zeile 65: [$id], [$name], [$phone]);
    • Zeile 44: Die Aufrufe folgen aufeinander: [getItem] liefert das Element, [set] weist ihm einen Wert zu und gibt das Element selbst zurück, [save] speichert es;
    • Zeilen 63–75: Ein Kontakt ist unveränderlich: Es wird ein neuer erstellt, der den alten im Array ersetzt. Eine Zuweisung ist ein Ausdruck, dessen Wert der zugewiesene Wert ist: [return $data['contacts'][$i] = new Contact(...)] ersetzt den Kontakt und gibt ihn zurück;
    • Zeile 80: [++] vor einer Variablen erhöht diese um 1 und gibt den neuen Wert zurück;
    • Zeile 92: [array_splice] entfernt ein Element aus dem Array und nummeriert die nachfolgenden Elemente neu;
    • Die Methoden geben [null] für einen nicht existierenden Kontakt zurück: Der Controller entscheidet über die Antwort.

// src/Controller/ContactsController.php: Links (GET) und Buttons (POST, DELETE)

namespace App\Controller;

use App\Form\ContactType;
use App\Model\Contact;
use App\Service\ContactsService;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\Form\SubmitButton;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\HttpKernel\Exception\AccessDeniedHttpException;
use Symfony\Component\Routing\Attribute\Route;

#[Route('/contacts', name: 'contacts')]
class ContactsController extends AbstractController
{
    public function __construct(private ContactsService $contacts)
    {
    }

    // der Kontakt oder eine 404-Antwort, wenn er nicht existiert
    private function contactOr404(?Contact $contact): Contact
    {
        return $contact ?? throw $this->createNotFoundException('unknown contact');
    }

    // ein LINK (<a href>): eine GET-Anfrage, die nichts ändert
    #[Route('', name: '', methods: ['GET'])]
    public function list(): Response
    {
        return $this->render('contacts/list.html.twig', ['contacts' => $this->contacts->list()]);
    }

    // GET /contacts/2: die Details; POST /contacts/2: einer seiner beiden Buttons
    #[Route('/{id<\d+>}', name: '_details', methods: ['GET', 'POST'])]
    public function details(Request $request, int $id): Response
    {
        $contact = $this->contactOr404($this->contacts->read($id));
        $form = $this->createForm(ContactType::class,
            ['name' => $contact->name, 'phone' => $contact->phone]);
        $form->handleRequest($request);
        if ($form->isSubmitted() && $form->isValid()) {
            ['name' => $name, 'phone' => $phone] = $form->getData();
            $duplicate = $form->get('duplicate');
            // isClicked: der Button, der das Formular gesendet hat
            if ($duplicate instanceof SubmitButton && $duplicate->isClicked()) {
                $copy = $this->contacts->add("$name (copy)", $phone);
                $this->addFlash('success', "The contact [$copy->name] has been created.");
            } else {
                $this->contacts->edit($id, $name, $phone);
                $this->addFlash('success', "The contact [$name] has been edited.");
            }
            return $this->redirectToRoute('contacts');
        }
        return $this->render('contacts/details.html.twig', ['contact' => $contact, 'form' => $form]);
    }

    // eine DELETE-Anfrage, simuliert durch ein POST-Formular (verstecktes Feld _method)
    #[Route('/{id<\d+>}', name: '_delete', methods: ['DELETE'])]
    public function delete(Request $request, int $id): Response
    {
        // das Anti-CSRF-Token des Formulars, spezifisch für diesen Kontakt
        if (! $this->isCsrfTokenValid("delete-contact-$id", $request->request->getString('_token'))) {
            throw new AccessDeniedHttpException('invalid anti-CSRF token');
        }
        $contact = $this->contactOr404($this->contacts->delete($id));
        $this->addFlash('success', "The contact [$contact->name] has been deleted.");
        return $this->redirectToRoute('contacts');
    }
}

    • Zeilen 46–54: [get('duplicate')] liefert den Button [duplicate] des Formulars; [isClicked()] stellt fest, ob er derjenige war, der das Formular abgesendet hat (der Test [instanceof SubmitButton] bestätigt dem Editor den Objekttyp). // Ohne JavaScript werden diese Formulare einfach ohne Bestätigung gesendet.
(() => {
  const modal = document.getElementById('confirmation-modal');
  const message = document.getElementById('confirmation-modal-message');
  let pending = null; // das Formular, das gesendet wird, wenn der Benutzer bestätigt

  // 1. Wir fangen das Absenden der zu bestätigenden Formulare ab
  document.querySelectorAll('form[data-confirmation]').forEach((form) => {
    form.addEventListener('submit', (event) => {
      event.preventDefault(); // das Absenden wird ausgesetzt
      pending = form;
      message.textContent = form.dataset.confirmation;
      modal.classList.remove('d-none'); // das Fenster erscheint
    });
  });

  // 2. die beiden Buttons des Fensters
  modal.addEventListener('click', (event) => {
    const action = event.target.dataset.action;
    if (action === 'yes') {
      pending.submit(); // Absenden, OHNE das Ereignis 'submit' erneut auszulösen
    } else if (action === 'no') {
      modal.classList.add('d-none');
      pending = null;
    }
  });
})();
    • Zeile 3: Der Code ist in eine anonyme Funktion eingeschlossen, die sofort ausgeführt wird; ihre Variablen stören die der anderen Skripte auf der Seite nicht;
    • Zeilen 4–6: das Fenster, die Stelle der Nachricht und das Formular, das auf Bestätigung wartet;
    • Zeilen 9–17: Für jedes Formular mit einem [data-confirmation]-Attribut wird das Ereignis [submit] – ausgelöst beim Absenden des Formulars – abgefangen. [preventDefault()] unterbricht das Absenden; das Formular wird in die Warteschleife gestellt, und seine Nachricht ([dataset.confirmation], der Wert des Attributs [data-confirmation]) wird im Fenster angezeigt, das erscheint;
    • Zeilen 20–28: ein einziger Handler für Klicks im Fenster: [event.target] ist das angeklickte Element; sein Attribut [data-action] gibt an, um welchen Button es sich handelt. „Ja“ sendet das wartende Formular mit der Methode [submit()] ab, die – anders als ein Klick auf einen Button – das Ereignis [submit] nicht auslöst (sonst würde das Fenster wieder erscheinen); „Nein“ blendet das Fenster aus.

    Ohne [JavaScript] wird das Formular einfach ohne Bestätigung abgesendet: Die Seite bleibt benutzbar. Das ist inkrementelle Verbesserung: [JavaScript] fügt Komfort hinzu, aber die Anwendung hängt nicht davon ab.
